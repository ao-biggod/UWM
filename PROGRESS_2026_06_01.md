## Phase C2: State Spacing Investigation

### C2-1: State Spacing Audit

**Finding**: Eval `state_buffer` collects states at policy-call boundaries. With `n_action_exec=8`,
states are 8 physical steps apart, while training uses 1-step-apart states.

```
Old wrapper: state_buffer = [t-8, t]  ← distribution mismatch with training
Training:    state_buffer = [t-1, t]  ← consecutive states
```

### C2-2: Replan Frequency Ablation (50ep)

| n_exec | Spacing | Score |
|--------|---------|-------|
| 8 | 8-step | 0.162 |
| 4 | 4-step | 0.160 |
| 2 | 2-step | 0.181 |
| 1 | 1-step | 0.105 |

### C2-3: Fixed-Buffer Eval (n_exec=8, spacing=1)

| Run | Spacing | Score | Action Delta |
|-----|---------|-------|-------------|
| old-wrapper | 8-step | 0.191 | 12.6 |
| fixed-buffer | 1-step | 0.246 | 6.5 |

**Conclusion**: State spacing is a real issue but NOT the primary bottleneck.
Fixing it gives +0.055. Score remains far from DP's 0.73.

### E0-P: Adapter Parity Test

**Critical finding**: Our first E0-2 attempt scored 0.122 due to adapter bugs:
1. Double normalization (manual normalize + policy internal normalize)

- `predict_action({'obs': tensor[B,2,20]})` → `{'action': tensor[B,8,2]}` raw actions
- No manual normalize/unnormalize needed
- Obs format: first 20 dims of PushTKeypointsEnv output (= keypoints(18) + agent_pos(2))

**Parity test: obs max_abs_diff=0.0, action max_abs_diff=0.0 → PASSED**

## Critical Adapter Bug Fix (Cross-Phase)

Throughout today, a recurring issue was the policy adapter contract.

### DP Official Lowdim `predict_action` Contract (verified from source)

```
Input:  {'obs': tensor[B, >=2, 20]}
Output: {'action': tensor[B, 8, 2]}  ← already raw, already sliced, already 8 steps

DO NOT manually normalize or unnormalize.
DO NOT slice action[:8] — the policy already returns 8 actions.
```

### Our B2/B3/UWM-DP-KP Policy Contract

```
Input:  obs tensor[B, 2, D]  (normalized externally)
Output: action tensor[B, 16, 2]  (normalized, needs unnormalize + [:8] slicing)
Model.sample() handles denoising.
Caller handles normalize → sample → unnormalize → clip → [:8] slicing.
```

### Key Difference

DP official: `predict_action()` handles normalize + denoise + unnormalize + slice internally.
Our models: caller must handle normalize + unnormalize + slice externally.

## Phase E2: UWM vs B3 Gap Analysis (2026-06-02)

### Context

UWM-DP-KP (0.397) scores far below B3 (0.790) despite both using:
- Same 20D keypoint obs
- Same eval stack (fixed-buffer, n_exec=8)
- No video/dynamics loss
- Same training (20k steps, no EMA, constant LR)

### Expert Playback Correction

- **Goal pose**: confirmed FIXED at `[256, 256, π/4]` (not random)
- **State diff**: 89-unit shift occurs when setting `block.angle` after `block.position` in PyMunk Space — body CoG ≠ geometric center causes position shift. This is a PyMunk physics behavior, only affects debug playback, not training/eval.
- **Conclusion**: When init state is correctly restored (ep1 diff=14 → score=0.938), action/env/reward semantics are verified correct.

| RMSE/expert_std | 0.179 | **0.105** |

UWM has better offline MSE (103 vs 297) but worse rollout (0.397 vs 0.790). Classic closed-loop instability signal.

### E2 Core Finding

Three sub-tasks converge:
- E2-0: UWM offline MSE better → model learns well from expert states
- E2-1: Static predictions aligned → same obs → similar output
- E2-2: UWM more consistent → not a sampling/variance issue

**Gap is in closed-loop dynamics**: UWM's AdaLN + causal attention makes it more sensitive to covariate shift. Even with similar first-action predictions, after 1-2 execution steps the state drifts, and UWM degrades faster than B3.

### E2-4 Proposal (NOT YET RUN)

Most promising single-variable ablation: change UWM backbone `causal_attn=False`.
Causal attention is designed for video prediction, not action-only. Bidirectional attention
should improve action trajectory coherence.
